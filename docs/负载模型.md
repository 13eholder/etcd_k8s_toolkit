# 负载模型

`etcd_k8s_bench` 施加的负载由固定存量、应用流量、周期流量与 Watch 订阅四部分组成。本文说明每部分实际发往 etcd 的请求形状；参数级协议细节以 [API 子集](../.agents/context/arch/design-docs/api-subset.md) 为准，目标口径以[设计目标](../.agents/context/arch/design-docs/design-goals.md)为准。

## 固定存量

| 资源 | 默认数量 | key 域 | 参与的流量 |
| --- | ---: | --- | --- |
| Pod | 40,000 | `/registry/pods/<namespace>/<name>` | 应用更新、主动读、Watch |
| Node | 2,000 | `/registry/minions/<name>` | NodeReady、周期 status、主动读、Watch |
| NodeLease | 2,000 | `/registry/leases/kube-node-lease/<node>` | 周期心跳、Watch |
| Deployment | 200 | `/registry/deployments/<namespace>/<name>` | 应用更新、主动读、Watch |
| ReplicaSet | 200 | `/registry/replicasets/<namespace>/<name>` | 应用更新、主动读、Watch |
| DaemonSet | 10 | `/registry/daemonsets/<namespace>/<name>` | 应用更新、主动读、Watch |

默认共 44,410 个资源 key。namespace 仅控制 key 分布，不另写 Namespace 对象。DaemonSet 占用 `node_count × daemonset_count` 个 Pod，其余 Pod 按 `pods_per_deployment` 分组，Deployment 与 ReplicaSet 数量相同；这些关系只推导基数，不执行控制器逻辑。

value 是指定大小的合成字节（默认 4096，NodeLease 512），不是可交给 apiserver 的 Kubernetes 对象。`compact_rev_key` 是 compaction 协调用的独立 journal，不是第七类资源。

## 应用流量

### 更新：单 key CAS

每次逻辑更新是一个 `KV/Txn`：compare 断言 `MOD(key)` 等于已持有的 mod_revision，成功分支为一个 Put，失败分支为一个点 Range。冲突后以返回的当前 KV/revision 重建后续 attempt，属于同一个逻辑操作；Create 冲突不自动重试。Put 的 `lease` 恒为 0，包括 NodeLease。

默认权重 Pod / Deployment / ReplicaSet / DaemonSet = 95 / 2 / 2 / 1；Node 与 NodeLease 不参与应用更新权重。

### 主动读

- 点读：完整对象 key 的线性一致 Range（`serializable=false`），覆盖 Pod / Node / Deployment / ReplicaSet / DaemonSet 五类。
- 有界列表：按各资源实际占用的 namespace/root 前缀轮转，逻辑目标为 `list_limit`（默认 100）；首页物理 `limit` 为 `min(500, 目标)`，后续页 `key` 为末条 key + NUL，`range_end` 不变，并固定第一页的 snapshot revision。

默认读写比 1:20；读权重 Pod / Node / Deployment / ReplicaSet / DaemonSet = 90 / 5 / 2 / 2 / 1；点读 / 列表 = 90 / 10。

## 周期流量

| 流 | 默认周期 | 请求 |
| --- | --- | --- |
| NodeLease 心跳 | 10s，确定性 5% jitter | 普通 KV 的 CAS 更新，`Put.lease=0`；不是 etcd native lease |
| Node status | 300s | Node key 的 CAS 更新 |
| Status | 10s | Maintenance Status 空请求，读取 header revision |
| compaction 协调 | 60s | 先做 journal Txn（`VERSION(compact_rev_key)` CAS）；有有效目标才发 Compact（logical，`physical=false`）。首次可能只建立 journal；CAS 冲突时接受其他协调者状态，本 tick 不抢占重试 |

周期流独立于应用更新速率预算。

## Watch

六类资源根各 `subscriptions_per_root`（默认 1）个订阅，范围为资源根前缀的半开区间，`start_revision=0`，`prev_kv=true`，`progress_notify=true`，并在 gRPC metadata 携带 `hasleader=true`。只有收到合法 Created 才算订阅就绪；断线后从已交付 revision + 1 恢复（尚无已交付事件时从保存的 Created header revision 恢复），不执行 relist，重连不抹除既有覆盖缺口。

## 不施压与已知限制

- native TTL / LeaseGrant：不施压；NodeLease 是普通 KV。
- 主动删除：ConditionalDelete 请求构造保留，当前不调度。
- 事务形状固定为一个 compare、一个 success、零或一个 failure；不产生嵌套 Txn 或多 key 多 op 事务。
- Range 响应校验未全覆盖：当前检查 snapshot revision 与 `more=true` 空页，未实现完整 key 范围、排序与跨页推进校验——不能视为对异常后端的完整检测。
- Watch 事件不按类型解码对象、不消费 selector/fragment；不模拟 watch cache、reflector 与控制器因果。

## 计量单位区分

逻辑更新、CAS attempt、物理 Txn、逻辑列表、Range page、Watch event 是不同计量单位：一次逻辑更新可能产生多个 Txn attempt，一次逻辑列表可能产生多个 Range page。报告中的速率与计数须按各自单位核对，详见[结果解读](结果解读.md)。
