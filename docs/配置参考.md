# 配置参考

`etcd_k8s_bench` 的完整配置输入与命令行覆盖。行为契约的权威来源见文末，本文是面向使用的字段说明。

## 输入与生效顺序

1. 基准输入为一份完整 JSON；省略 `--config` 时使用内嵌的 [synthetic-k8s.json](../etcd_k8s_bench/workloads/synthetic-k8s.json)。
2. `--config` 整体替换默认输入，不是局部合并；JSON 中出现未知字段直接拒绝。
3. 命令行标量覆盖在 JSON 之上最后应用，先于校验生效——可用命令行修正文件中的非法值。
4. `plan` 与 `run` 使用同一份生效配置与编译计划；`plan` 不连接后端。

## JSON 字段

### 顶层

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 负载名称，须为合法 workload name |
| `seed` | u64 | 合成 key 与周期 jitter 的种子；`0` 是合法的确定性种子 |

### topology：存量规模

| 字段 | 默认 | 约束 | 说明 |
| --- | --- | --- | --- |
| `node_count` | 2000 | >0 | Node 数量；同时决定 NodeLease 数量与 DaemonSet 消耗的 Pod 数 |
| `pod_count` | 40000 | >0 | Pod key 总数；须大于 `node_count × daemonset_count`，且剩余部分能被 `pods_per_deployment` 整除 |
| `namespace_count` | 100 | >0，≤ `pod_count` | 仅控制 key 分布，不创建 Namespace 对象 |

派生关系：DaemonSet 占用 `node_count × daemonset_count` 个 Pod；其余 Pod 按 `pods_per_deployment` 分组，Deployment 与 ReplicaSet 数量相同（默认各 200）。六类资源总 key 数为六类数量之和，默认 44,410。

### controllers：控制器拓扑

| 字段 | 默认 | 约束 | 说明 |
| --- | --- | --- | --- |
| `daemonset_count` | 10 | >0 | DaemonSet 数量，每个消耗 `node_count` 个 Pod |
| `pods_per_deployment` | 100 | >0 | 每个 Deployment（及 ReplicaSet）分组的 Pod 数 |

### value_size_bytes：value 大小

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `pods` / `nodes` / `deployments` / `replicasets` / `daemonsets` | 4096 | 合成字节数，须 >0 且不超过 `--max-message-size` |
| `node_leases` | 512 | 同上 |

value 是编码后的不透明合成字节，不是 protobuf 消息，也不等于网络字节数。

### load：应用流量

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `duration_ms` | 600000 | 测量窗口时长，正整数毫秒 |
| `update_rps` | 10000 | 应用逻辑更新目标速率；不是保证的物理 Txn/s |
| `read_ratio` | 1/20 | 主动读与更新的比例，按有理数速率取整；`denominator` 须 >0 |
| `update_weights` | pods 95 / deployments 2 / replicasets 2 / daemonsets 1 | 应用更新资源权重，总和须 >0 |
| `read_weights` | pods 90 / nodes 5 / deployments 2 / replicasets 2 / daemonsets 1 | 主动读资源权重，总和须 >0；NodeLease 不参与主动读 |
| `read_shape_weights` | point 90 / bounded_list 10 | 点读与有界列表权重，总和须 >0 |
| `list_limit` | 100 | 单次逻辑列表的目标条数；一次逻辑列表可能翻页为多个物理 Range |

### periodic：周期流量

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `node_lease_interval_ms` | 10000 | NodeLease 普通 KV 心跳周期 |
| `node_lease_jitter_percent` | 5 | 确定性抖动百分比，0–99 |
| `node_status_interval_ms` | 300000 | Node status 更新周期 |
| `status_interval_ms` | 10000 | Maintenance Status 周期 |
| `compact_interval_ms` | 60000 | compaction 协调周期；一次协调不必然产生 Compact RPC |

周期流独立于 `update_rps` 预算。

### watch：订阅

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `subscriptions_per_root` | 1 | 每个资源根的订阅数，>0；不随 Node 数放大 |
| `start_revision` | 0 | 订阅起点，须非负 |
| `prev_kv` | true | 请求事件携带 prev_kv |
| `progress_notify` | true | 请求服务端 progress 通知 |

### execution：执行资源与超时

| 字段 | 默认 | 约束 | 说明 |
| --- | --- | --- | --- |
| `workers` | 128 | >0 | 逻辑 worker 数，只影响执行能力，不取代目标到达速率 |
| `queue_capacity` | 4096 | ≥ `workers` | 总队列容量，按 key shard 分配；满则显式丢弃 |
| `request_timeout_ms` | 5000 | ≤ `operation_timeout_ms` | 单次 RPC 超时 |
| `operation_timeout_ms` | 10000 | — | 逻辑操作超时，从 worker 开始执行计时，不含排队 |
| `preparation_timeout_ms` | 180000 | >0 | 准备阶段总预算 |
| `drain_timeout_ms` | 10000 | >0 | 截止后 drain 预算 |
| `watch_teardown_timeout_ms` | 5000 | >0 | Watch 回收预算 |

以上时长字段均为正整数毫秒。

### report：观测

| 字段 | 默认 | 约束 | 说明 |
| --- | --- | --- | --- |
| `bucket_ms` | 1000 | ≤ `duration_ms` | 报告时间桶宽度 |
| `memory_limit_mib` | 128 | >0 | 观测内存预算；有界观测估算，不是进程绝不 OOM 的保证 |

## 命令行覆盖

`plan` 与 `run` 共用以下参数：

| 参数 | 覆盖字段 | 说明 |
| --- | --- | --- |
| `--config <path>` | — | 整体替换 JSON 输入 |
| `--nodes` | `topology.node_count` | |
| `--pods` | `topology.pod_count` | |
| `--namespaces` | `topology.namespace_count` | |
| `--pod-size` | `value_size_bytes.pods` | 只改 Pod，其余资源 value 不变 |
| `--seed` | `seed` | |
| `--update-rps` | `load.update_rps` | |
| `--duration` | `load.duration_ms` | 接受 `600s`、`2500ms` 等形式 |
| `--workers` | `execution.workers` | |
| `--queue-capacity` | `execution.queue_capacity` | |
| `--request-timeout` | `execution.request_timeout_ms` | 如 `5s`、`250ms` |
| `--operation-timeout` | `execution.operation_timeout_ms` | 如 `10s`、`3m` |
| `--max-message-size` | 不进 JSON | gRPC 收发消息上限，默认 64MiB；各 value 大小不得超过它 |

`run` 独有：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--endpoint` | `http://127.0.0.1:2379` | etcd gRPC endpoint，必须指向专用空实例 |
| `--metrics-listen` | `127.0.0.1:9898` | Prometheus exporter 监听地址 |

## 校验失败即拒绝

配置在校验通过前不接触后端。除上表所列约束外：三类权重总和须为正；`namespace_count ≤ pod_count`；`queue_capacity ≥ workers`；`request_timeout ≤ operation_timeout`；`bucket_ms ≤ duration_ms`；剩余 Pod 须为正且按 `pods_per_deployment` 整除。参数或配置错误以退出码 2 结束，不产生报告。
