# 结果解读

`run` 输出单份 JSON 报告。本文说明报告结构、计数守恒与常见误读；实现口径的权威来源见文末。

## 报告结构

报告恰有九个顶层字段：

| 字段 | 内容 |
| --- | --- |
| `schema_version` | 报告 schema 版本 |
| `experiment` | 实验状态（是否完成及原因） |
| `resolved_config` | 生效配置（JSON 经命令行覆盖后的最终值） |
| `plan` | 编译后的投放计划 |
| `timing` | 准备、测量、drain、Watch teardown 各阶段计时 |
| `preparation` | 准备阶段摘要 |
| `measurement` | 测量窗口内的计数、时间桶与延迟分布 |
| `drain` | 截止后的收尾计数 |
| `accounting` | 守恒核对结果 |

参数或配置错误（退出码 2）不产生报告；执行失败（退出码 1）尽可能保留已发生阶段的部分结果，未开始阶段保持空状态，不制造观测。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 实验完成；不代表压力达标或 Watch 观测完整 |
| 1 | 执行、准备或生命周期失败 |
| 2 | 参数或配置错误，无运行报告 |
| 130 | 中断，保留可获得的部分报告 |

未配置 SLO 阈值时，工具只报告事实，不自行判定承载是否达标。

## 分别回答三个问题

| 问题 | 判定载体 | 不能混同 |
| --- | --- | --- |
| 实验是否完成 | `experiment.status` 与退出码 | 有丢弃/错误不必然执行失败 |
| 目标是否投出、后端接住多少 | planned / offered / missed_schedule / dropped_full / accepted / completed / failed / canceled，吞吐与延迟 | 后端没收到的漏投不是后端拒绝 |
| 测量窗口与观察是否完整 | `measurement_complete`、Watch coverage、`observation_complete` | 完整观察不等于请求全部成功 |

## 计数守恒

每条流的计划按完整配置时长固定：

- `planned = offered + missed_schedule + not_offered_after_stop`
- `offered = accepted + 显式拒绝`

accepted cohort 在窗口内完成、drain 完成与最终取消之间守恒。令 B/U 为截止前/后 started，Tb/Ta 为截止前/后 succeeded+failed，Cq/Cr 为两类取消，则：

- `accepted = Tb + Ta + Cq + Cr`
- `B + U = Tb + Ta + Cr`
- `Tb ≤ B ≤ accepted`，`U ≤ accepted − B`；不能要求 `Ta ≤ U`——截止前在途的工作可以在 drain 完成。

`cutoff_queued = accepted − B`、`cutoff_running = B − Tb` 是最终 cohort 导出的残差，包含可能早于截止发生的取消，不是截止瞬间的实时队列快照。

## 常见误读

1. **逻辑速率 ≠ 物理请求数。** 一次逻辑更新可能产生多个 Txn attempt，一次逻辑列表可能翻页为多个 Range page；报告中的速率与计数按各自单位核对，不互相换算。
2. **timeout 与 result_unknown 是可重叠的 failed 子集**，相加不是总失败数。
3. **dropped_full 是目标 key shard 的队列满**，不代表所有 worker 队列都满。
4. **exit 0 不代表压力达标**：后端过载但实验正常跑完仍返回 0。
5. **取消不产生完成样本**：censored 另列；HDR 的 `sample_count + overflow` 才是已观测数量，overflow-only 时分位数为 null、max 仍精确。
6. **两套延迟口径不同**：HDR 向上取整（至少 1µs），在线微秒指标向下截断；不能互推均值与分位数。HDR 成功与错误共用，不提供 per-outcome 分布；timeout 样本是客户端观察到终止的延迟，不证明后端实际完成时间。
7. **protobuf payload 字节 ≠ HTTP/2/TLS/网络字节**。
8. **Watch coverage 只累计真实可观察区间**，重连不抹除先前缺口；当前 ready 与曾经 ready 不同。
9. **在线指标是辅助观测**：Prometheus 无 p99（精确分位数读最终 JSON），采样 CPU/RSS 峰值不是精确进程最大值。

## 比较后端的原则

比较两个后端时，同时报告实际 offered / missed_schedule / dropped_full、完成吞吐与延迟，区分生成器限制与后端限制；不以配置速率、退出码或单次结果宣称后端容量。档位比较保持对象形状、value 与周期不变，只改变更新速率。
